# 장 → 하위절 세부 분리

이미 장별로 나눈 hwpmd Markdown(각 파일에 `<!--@hwp-source-begin-->`~`<!--@hwp-source-end-->` 원문 구간이 있는 파일)을 **하위절 단위**로 더 잘게 나눈다.

- **계층 분류**: h2 장 → h3 `N-N` → h4 `가.` → h5 `(N)` 순서로 실제 헤딩 계층대로 재귀 분리.
- **무손실**: 나눈 조각을 DFS 순서로 이으면 원 장 조각과 바이트 단위로 동일하다(생성 시 assert 검증, `merge`로 재검증).
- **표 분류**: 각 표를 장·절별 목록(카탈로그)과 앵커째 별도 `.md` 복사본으로 뽑는다. 본문은 그대로 두므로 무손실이 유지된다.

전제: `split-hwp-chapters`로 장 분리가 끝나 있어야 한다. 원본 HWP만 있으면 그 스킬을 먼저 실행한다. 파이프라인 좌표계(마커·앵커·매니페스트)는 [../split-hwp-chapters/references/pipeline.md](../split-hwp-chapters/references/pipeline.md)를 공유한다.

## 계층·라벨 규칙

hwpmd 헤딩 레벨과 분류 라벨의 대응(원본 서식 기준). 라벨은 헤딩 레벨이 아니라 **제목 텍스트 패턴**에서 뽑으므로, 서식이 규칙적일 때 아래 대응이 성립한다(7장처럼 레벨이 불규칙하면 어긋날 수 있다):

| 레벨 | 예 | 라벨 |
|---|---|---|
| h2 | `5. 연구개발성과의 사업화 전략 및 계획` | 장 (`5`) |
| h3 | `5-1. 국내·외 기술과 시장 현황` | `5-1` |
| h4 | `가. 인적사항` | `가` |
| h5 | `(1) 국내 기술의 수준 및 시장 동향` | `(1)` |

각 절은 실제 문서의 헤딩 계층대로 나뉜다. 예: 5장은 h4가 없어 `5-1 → (1),(2)`, `5-2 → (1),(2),(3)`가 그대로 나온다. 7장은 h3 아래 `가.`(h4) 계층이 있어 한 단계 더 깊어진다.

## 1. 세부 분리 실행

```bash
python .claude/skills/subsplit-hwp-sections/scripts/subsplit_hwpmd.py split \
  --parts-dir 연구개발계획서_장별 \
  --output    연구개발계획서_세부
```

옵션:
- `--parts-dir DIR` — 장 파일 폴더(`README.md`, `_`로 시작하는 파일은 자동 제외). 또는 `--input 한장.md`로 한 파일만.
- `--output DIR` — 세부 분류 출력 폴더(필수).
- `--max-level {3,4,5,6}` (기본 5): 어디까지 세분화할지. `5` = `(N)`까지, `4` = `가.`까지, `3` = `N-N`까지(`6` = h6까지, 통상 불필요). 헤딩 계층이 불규칙한 장(예: 7장)은 `--max-level 4`나 `3`으로 깊이를 제한하면 깔끔하다.

출력 `{"output","chapters","leaves","tables","lossless"}`. 무손실이 아니면 생성 도중 `AssertionError`로 중단되므로, 정상 종료 시 출력의 `lossless`는 항상 `true`다(참고: `merge`로 언제든 다시 검증할 수 있다).

## 2. 산출물 구조 (중첩 폴더)

```
연구개발계획서_세부/
  05_연구개발성과의_사업화_전략_및_계획/
    00_5_머리.md                         # 장 제목 + 하위절 앞 도입부
    01_5-1_국내_외_기술과_시장_현황/
      00_5-1_머리.md
      01_(1)_국내_기술의_수준_및_시장_동향.md
      02_(2)_국외_기술의_수준_및_시장_동향.md
    02_5-2_.../ 01_(1)_..md  02_(2)_..md  03_(3)_..md
    03_5-3_표준화_전략.md                # 하위절 없으면 잎 파일
    _tables/S2.P0445.T00.md              # 표 복사본(앵커 포함)
    _tables.md                           # 이 장의 표 목록
    _구조.md                             # 하위 트리 개요
    _세부_매니페스트.json                # 재병합용(순서·해시·표)
  _tables_index.{json,md}                # 전체 표 색인
  README.md                              # 전체 트리 요약
```

- 파일명 앞 2자리(`01_`, `02_`)는 문서 순서, 그 뒤 라벨(`5-1`, `(1)`, `가`)은 원본 그대로 유지한다.
- 하위절이 있는 절은 폴더가 되고, 폴더의 `00_..._머리.md`가 그 절 자신의 도입부(자기 헤딩 + 하위절 전 본문)를 담는다. 이 머리 파일까지 순서대로 이어야 무손실이 성립한다.

각 잎/머리 파일은 장 파일과 같은 형식이다: 프런트매터 + `# 제목` + `<!--@hwp-source-begin-->` 원문 조각 `<!--@hwp-source-end-->`. **원문 조각의 `<!--@hwp ...-->` 앵커·`data-hwp-*`·표 속성은 삭제·개명 금지**(재병합 좌표).

## 3. 표 분류

- **복사본**: `<장폴더>/_tables/<노드>.md` — `<!--@hwp table=노드-->`와 `<table ...>` 전체를 그대로 담고, 프런트매터에 행×열·소속 절·캡션(추정)을 기록. 본문에서 제거하지 않으므로 무손실이 유지된다.
- **장별 목록**: `<장폴더>/_tables.md`.
- **전체 색인**: `_tables_index.json` / `_tables_index.md` — 표 노드, 크기, 소속 절, 캡션.
- 캡션은 표 바로 앞의 가장 가까운 헤딩 제목을 추정치로 넣는다(정확한 표 제목이 아닐 수 있으니 참고용).
- 표 중심으로 편집하려면 복사본을 고치고, 반영은 아직 자동이 아니므로 본문 원문 구간에도 같은 표를 직접 반영한다(복사본은 분류·열람용).

## 4. 재병합·검증

세부 절을 장 조각으로 되돌려 무손실을 검증한다.

```bash
# 검증만: 각 장 폴더의 절들을 이어 원 장 조각 해시·앵커 구조와 대조
python .claude/skills/subsplit-hwp-sections/scripts/subsplit_hwpmd.py merge --output 연구개발계획서_세부

# 무편집 반영: 내용이 원본과 동일한 장만 장 파일 SOURCE 구간을 갱신
python .claude/skills/subsplit-hwp-sections/scripts/subsplit_hwpmd.py merge \
  --output 연구개발계획서_세부 --write-back 연구개발계획서_장별

# 편집분 반영: 절 파일을 편집(예: 템플릿 채우기)한 경우. 앵커 구조가 유지되면 기록
python .claude/skills/subsplit-hwp-sections/scripts/subsplit_hwpmd.py merge \
  --output 연구개발계획서_세부 --write-back 연구개발계획서_장별 --allow-edits
```

출력 요약: `all_content_identical`(무편집 여부), `all_structure_ok`(앵커 수 보존 여부), `edited_chapters`(편집된 장 목록). 기본 `--write-back`은 **내용이 동일한 장만** 기록한다. 절 파일을 편집했다면 `--allow-edits`를 붙여야 하며, 이때도 각 조각의 최상위 앵커 수가 매니페스트와 일치(구조 보존)해야 기록된다. 이후 상위 파이프라인으로 장→마스터→(원본 HWP 복원)까지 이어진다:

```bash
python tools/merge_hwpmd_chapters.py --master 연구개발계획서.md \
  --parts-dir 연구개발계획서_장별 --out 연구개발계획서_장별_병합.md
```

무편집 상태에서 이 2단계 체인은 마스터 본문을 바이트 단위로 재현한다(검증 완료).

## 5. 편집 워크플로우

1. `split`으로 세부 분리 → 원하는 절 파일(예: `01_(1)_국내_기술....md`)만 열어 `hwp-source` 구간 편집.
2. 앵커·`data-hwp-*`·표 구조는 보존. 표는 필요 시 `_tables/` 복사본을 참고.
3. `merge --write-back 연구개발계획서_장별`로 장 파일에 반영·검증.
4. `tools/merge_hwpmd_chapters.py`로 마스터에 반영.

## 주의·한계

- **헤딩 불규칙 장**: 원본에서 같은 의미의 항목이 서로 다른 헤딩 레벨로 찍혀 있으면(7장 `(2)/(3)`가 h5로, `가.~아.`가 h4로 찍힌 경우 등) 자동 트리가 의미상 완벽히 정렬되지 않을 수 있다. 무손실은 항상 유지되며, `--max-level`로 깊이를 제한해 완화한다.
- **긴 경로**: 깊은 절 + 긴 한글 제목은 Windows 260자 경로 한계를 넘길 수 있어 스크립트가 확장 경로(`\\?\`)로 기록한다. 그래도 `--output`은 짧은 경로에 두는 것이 안전하다.
- **표 캡션은 추정치**다. 정식 표 번호·제목이 필요하면 원문에서 직접 확인한다.
- 입력 파일에 `<!--@hwp-source-begin/end-->`가 정확히 1쌍 없으면(잘못된 장 파일) 해당 파일에서 멈춘다.

## Windows·UTF-8 실행

- `python -X utf8 ...`로 실행한다. 모든 산출은 `newline=""`로 기록되어 `\r\n`/`\n`이 보존되므로 에디터의 자동 개행 변환을 끄고 편집한다.
- 한글 파일은 `Get-Content -Encoding UTF8`로 읽는다. 콘솔 글자 깨짐을 파일 손상으로 단정하지 않는다.
