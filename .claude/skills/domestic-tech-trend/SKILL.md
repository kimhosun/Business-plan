# 국내 기술개발 동향 조사·작성

**정찰(에이전트 3인) → 계획 → 수집 → 출처주석 변환 → 템플릿 작성 → 인용검증** 6단계.
단계를 건너뛰지 않는다. 특히 **3단계(실제 다운로드)를 하지 않고 4·5단계로 가지 않는다** —
기억으로 쓴 동향 문서는 이 스킬의 산출물이 아니다.

기본값(사용자가 달리 말하지 않으면):

| 항목 | 기본값 |
|---|---|
| 산출 위치 | `research/<주제슬러그>/` (저장소 루트 기준) |
| 조사 범위 | 국내 중심, 해외는 비교 근거로만 최소 |
| 템플릿 | 사용자가 준 `.md` 파일 경로. 없으면 `template.example.md`, 또는 rnd-write-* 절 지침 |
| 자료 수 | 핵심(tier 1) 8~12건 + 보강(tier 2) 5~10건 |

작업 시작 시 TodoWrite 로 6단계를 등록하고 단계마다 갱신한다.

## 0단계. 착수 확인 (짧게)

사용자 요청에서 다음이 비어 있으면 **한 번에 모아서** 묻는다(AskUserQuestion). 하나씩 되묻지 않는다.

1. **기술의 범위** — "수소"처럼 넓으면 조사가 흩어진다. 하위 기술·응용처·공정 단계 중 어디인지.
2. **문서의 용도** — 연구개발계획서 1-2절인지, 내부 검토자료인지, 분량은 어느 정도인지.
3. **템플릿 경로** — 있으면 경로, 없으면 예시 템플릿으로 진행함을 알린다.

범위가 이미 충분히 좁고 템플릿 경로도 왔으면 **묻지 말고 바로 1단계**로 간다.

폴더를 만든다:

```bash
python .claude/skills/domestic-tech-trend/scripts/init_research.py \
  --topic "고체산화물 수전해(SOEC) 스택" --root research --today 2026-08-13
```

## 3단계. 수집 — 실제로 내려받는다

```bash
python .claude/skills/domestic-tech-trend/scripts/fetch.py --dir research/<슬러그>
```

- 이미 받은 파일은 건너뛴다(멱등). 다시 받으려면 `--force`, 일부만 `--only S03,S07`.
- 결과는 `raw/manifest.json` 에 `sha256`·`fetched_at`·`status` 까지 기록된다.
- **실패는 정상이다.** 국내 공공 사이트는 로그인·JS 렌더링·뷰어 전용이 흔하다.

실패분 처리 — **사용자에게 떠넘기기 전에 먼저 시도한다**:

1. WebSearch 로 같은 문서의 **다른 배포처**(기관 발간물 페이지, 국회도서관, 보도자료 첨부)를 찾는다.
2. WebFetch 로 목록 페이지를 읽어 **실제 첨부파일 직링크**를 뽑아 `url` 을 고친 뒤 재시도한다.
3. 그래도 막히면 사용자에게 **정확한 페이지 URL 과 저장할 파일명**을 알려주고 직접 저장을 요청한다.
   저장 후 `sources.yaml` 의 해당 항목에 `local: raw/<파일명>` 을 적고 `fetch.py` 를 다시 돌린다.

tier 1 자료가 절반 이상 실패하면 **진행하지 말고** 대체 자료로 계획을 고쳐 2단계로 돌아간다.

## 4단계. 변환 — 문단마다 출처를 박는다

```bash
python .claude/skills/domestic-tech-trend/scripts/to_md.py --dir research/<슬러그> --tables
```

산출: `md/S01_….md` … + `md/INDEX.md`

- 파일 머리 YAML frontmatter = 출처 원장(제목·기관·연도·URL·수집일시·sha256·원본경로).
- 모든 문단 앞에 **`[S01:p12:4]`** 마커. 형식과 활용은 [references/citation.md](references/citation.md).
- `--tables` 는 pdfplumber 로 PDF 표까지 뽑는다. 시장규모·스펙 표가 중요한 자료에 쓴다.

변환 후 **반드시 눈으로 확인**한다:

```bash
head -40 research/<슬러그>/md/S01_*.md
grep -c '^\[S' research/<슬러그>/md/*.md      # 파일별 문단 수
```

- "추출된 본문 없음" → 스캔 PDF(이미지) 또는 JS 페이지. OCR 은 이 스킬 범위 밖이므로
  사용자에게 알리고 대체 자료를 찾는다. **빈 파일을 근거로 쓰지 않는다.**
- 문단 수가 비정상적으로 적으면(예: 100쪽 PDF 인데 20문단) 2단 조판·표 위주 문서다.
  `--tables` 를 켜고 다시 돌리거나, 해당 자료는 Read 로 직접 읽어 보완한다.
- 한자·깨진 글자가 많으면 인코딩 문제 — 원본을 Read 로 확인한다.

## 5단계. 작성 — 템플릿·지침에 맞춰 쓴다

### 입력

1. **템플릿**: 사용자가 준 `.md`. 없으면 [template.example.md](template.example.md).
   - `{{이름}}` = 채울 자리 · `※` 줄 = 작성지침(결과물에 남기지 않는다) · 표는 열 구조 유지, 행만 늘림
   - 연구개발계획서 절이면 `rnd-proposal-writer` 의 해당 `rnd-write-*` 절 지침을 템플릿으로 쓴다
2. **근거**: `md/INDEX.md` 로 전체를 파악하고, 필요한 md 파일을 Read 로 읽는다.
   자료가 많으면 절별로 필요한 파일만 읽는다.

### 작성 규칙

- **모든 사실 문장 끝에 마커를 단다.** 수치·연도·비율·기관명이 들어간 문장은 예외 없이.
  ```
  국내 SOEC 스택은 2023년 5kW급 실증까지 도달했다. [S03:p12:2][S07:p4:1]
  ```
- **마커를 지어내지 않는다.** 근거를 못 찾았으면 `[근거미확보]` 를 남기고 6단계에서 사용자에게 보고한다.
  그럴듯한 문장을 근거 없이 채우는 것이 이 작업의 가장 큰 실패다.
- **수치는 기준연도·단위·출처기관을 함께 쓴다.** 자료마다 다르면 상위 등급(정부·통계)을 본문에,
  나머지는 각주로 병기한다(등급은 [references/sources.md](references/sources.md) 참조).
- **해외는 비교 근거로만.** 기준연도·측정조건이 다르면 비교하지 말고 각각 병기한다.
- **시사점·공백 절은 앞 절의 사실에서만 도출한다.** 여기서 새 사실을 처음 꺼내지 않는다.
- 어투는 템플릿(또는 절 지침)을 따른다. 연구개발계획서면 개조식·명사형 종결.

`research/<슬러그>/report.md` 로 저장한다(마커를 살린 채).

## 함정

- **정찰 에이전트의 URL 을 그대로 믿지 않는다.** 3단계에서 실제로 받히는 것만 근거가 된다.
- **`research/*/raw/` 는 커밋하지 않는다**(저작권·용량). `.gitignore` 에 등록되어 있다.
  `md/`·`plan.md`·`report.md` 는 커밋해도 된다.
- **`.hwp` 첨부는 먼저 `.hwpx` 로 변환**한다 — 저장소 규칙(CLAUDE.md). 변환 스크립트는
  `.claude/skills/hwpx-yaml-roundtrip/scripts/hwp2hwpx.py` (한컴오피스 필요).
- **PDF 쪽번호 ≠ 마커의 `p`값**. 마커의 p는 파일의 물리적 쪽 순번이다. 최종 참고문헌에
  쪽수를 적을 때는 원본의 인쇄 쪽번호를 확인해 쓴다.
- **같은 자료를 여러 번 받지 않는다.** `fetch.py` 는 멱등이므로 그냥 다시 실행하면 된다.
- 이 스킬은 **국내 동향 조사·작성**까지다. HWP/HWPX 문서로 만드는 것은
  `hwpx-yaml-roundtrip`, 계획서 절 문체는 `rnd-proposal-writer` 가 맡는다.
