# [지침] 절 1-1 「개발 대상 기술·제품의 개요」 상세

> 원본: `절_1-1_개발대상_기술제품_개요.md` · 대응 스킬: `rnd-write-1-1-overview` · 적용 절: ### 1-1. 개발 대상 기술·제품의 개요 (문서에 따라 "기술ㆍ제품")
>
> 자동 생성 문서 — 아래 `@guideline-auto` 구간은 sync 가 재생성합니다.

**역할**: 과제가 **무엇을 개발하는지(정의)**와 **어디까지 다루는지(범위)**를 도입부에서 개조식으로 선언. 문제의식·시장과 연결.

## 반드시 적용할 공통원칙
- **§1 문체·종결형** — **개조식 명사형 종결**을 기본으로 한다: `~개발 / 구축 / 수립 / 검증 / 확보 / 도출 / 분석 / 함 / 음 / 예정임 / 계획임`.
- **§2 마커·번호 계층** — 계층 순서: `□ 또는 [대괄호 머리말] → ㅇ(◦) → -(—) → ·`.
- **§3 정량화·근거 표기** — 목표·현황·효과에 **수치+단위**를 붙인다: `MW·GW·mm·%·톤·건·명·억원·CAGR` 등.
- **§4 표 서식 관행** — 상당수 절은 자유 서술이 아니라 **정형 표 채우기**다. 표의 열·행 구성과 코드·관계식(예: 예산 K=직접비, M=K+L)을 유지한다.
- **§5 용어·기관명** — 영문 약어는 **최초 등장 시 정의**(예: PWHT, BIM, MSR, IEC, IACS, TRL/CRL).
- **§8 금지사항** — 특정 참조문서의 문장을 **그대로 베끼기**(주제·문구는 새로 작성).

## 골격 지침
- **연구개발기술(제품)의 정의 및 범위** — 대분류 머리(`□`/`◦`)로 시작.  · **정의**: 과제 한 줄 정의(무엇을 · 무엇 기반으로 · 무엇을 위해 개발).  · **세부정의 n / 범위 n**: 세부기술을 번호로 나누고 각 세부기술의 범위 1~3개 서술.
- (선택) 개념도·비교도 삽입 지점: `< 제목 >` 캡션 + 그림 자리 [공통원칙 §3].
- 표지성 메타정보(전문기관·과제번호 등)는 **개요 본문에 넣지 말 것**(원문의 PDF 표 평탄화 잡음, [공통원칙 §8]).

## 문서별 변형 지침
- **D1형(계층 전개)**: `□ 정의 및 범위` → 정의 → 세부정의1/범위1·2 → 세부정의2/범위1~3… 로 **세부기술을 계층화**. 다세부·연구형에 적합.
- **D3형(배경+요소기술표)**: `#### (1) 개발 배경` + `#### (2) 개발 요소기술별 필요성`(요소기술명/개발기관/필요성/특장점 **4열 표**). **다요소·다기관·실증형**이면 이 표형 권장.
- **D11형(상위→하위 좁혀가기)**: `◦ 사업 개요` → `◦ 상위개념(예: CCUS) 정의 및 범위` → `— 개발대상 정의`. 상위 프레임에서 대상으로 수렴, 간결형.
- **판단 기준**: 세부기술이 많고 단일 흐름이면 D1형, 요소·기관이 병렬로 많으면 D3 표형, 큰 정책·가치사슬 맥락이 중요하면 D11형.

## 문체·표기 지침
- **정의는 반드시 한 줄로 먼저** 못박고 그 뒤에 범위를 계층 전개(순서 고정).
- 개요 단계부터 **핵심 정량목표 1개 이상**을 심는다(수심 m·용량 MW급·두께 mm·절감 %·중량 톤·압력/온도). 근거 있는 값만 [공통원칙 §3].
- D3형 도입 정형: **"본 연구에서는 …을 목표로 함"** + 공법/제품명을 따옴표로 명명.
- 마커 계층은 택1한 문서 스타일로 절 내부 일관 [공통원칙 §2]. 종결은 명사형 [공통원칙 §1].

## 체크리스트
- [ ] 표준 제목 사용, 정의(1줄) + 범위(세부기술별) 구조가 드러남.
- [ ] 문서 유형 택1 후 마커 계층 일관.
- [ ] 핵심 정량목표 1개 이상 포함.
- [ ] 영문 약어 최초 정의·참여기관 괄호 병기 [공통원칙 §5].
- [ ] 그림/표 캡션·출처 표기, 특정 참조문서 문장 복붙 없음 [공통원칙 §8].
